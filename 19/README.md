# CompactTrie

Префиксное дерево в плоском `ArrayBuffer` (символ + флаги + child/sibling). Рядом — `Trie` из `another.ts` на массиве узлов с `Map`.

## Запуск

```sh
npx tsx ./19/index.ts
npm run 19:bench
NODE_OPTIONS='--expose-gc' npm run 19:bench
```

## Бенчмарк

`19/index.bench.ts`: 10 000 слов, алфавит по 26 символов.

Режимы CompactTrie: латиница `char=1`, кириллица `char=2`, иероглифы **`char=4`** (полный запас под code point).

### Сравнение размера памяти (прогон)

| Алфавит   | CompactTrie              | Trie(Map) retained | Trie / CompactTrie |
| --------- | ------------------------ | ------------------ | ------------------ |
| Латиница  | **289.59 KB** (`char=1`) | **~8.79 MB**       | **×31.1**          |
| Кириллица | **326.13 KB** (`char=2`) | **~9.64 MB**       | **×30.3**          |
| Иероглифы | **398.30 KB** (`char=4`) | **~9.62 MB**       | **×24.7**          |

У иероглифов `char=4` → **11 B/node**, used выше, чем при `char=2` (~326 KB), поэтому выигрыш к Map чуть меньше (~×25 вместо ~×30). Для BMP CJK хватило бы и `char=2`; `char=4` — запас / единообразие с полным code point.

### CompactTrie: ширина поля символа (~37k nodes)

| char | B/node | used ≈ |
| ---- | ------ | ------ |
| 1    | 8      | 290 KB |
| 2    | 9      | 326 KB |
| 3    | 10     | 362 KB |
| 4    | 11     | 398 KB |

### Lookup (прогон)

|             | hz (порядок) |
| ----------- | ------------ |
| CompactTrie | ~103–131     |
| Trie (Map)  | ~2 180–2 850 |

Map быстрее примерно в **×21–24** (в этом прогоне; обычно ~×25–30). `char=4` на CJK lookup не замедляет заметно относительно `char=2`.

## Выводы

1. **CompactTrie всё ещё на порядок компактнее Map** — даже с `char=4` на иероглифах (~×25).
2. **Шире поле символа → больше used:** `char=1/2/4` ≈ 290 / 326 / 398 KB при тех же nodes.
3. **Иероглифы BMP можно хранить в `char=2`**; `char=4` дороже по памяти, но безопаснее для полного Unicode.
4. **Поиск быстрее у Map**; CompactTrie — про плотность buffer.
